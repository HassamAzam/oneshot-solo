## New Breakage in the Fix Diff

No Critical or Important problems. Nothing in the diff gives the session more reach. Every change keeps or narrows it: secret-guard denies more paths, mr-gate checks project and branch, the server runs in `modify` with a deny regex and a strict allowlist, and the app env is a whitelist. No real credential appears; test fixtures use obviously fake values (`glpat-a`, `qa@example.com:pw`). The first-result-frame rule is intact: `foldFrame` still settles on the first result frame, ignores later ones, and only checks rate-limit tags while unsettled. The abort and resume paths are unchanged in shape and now carry a session id. The merge gate's decision is unchanged; only the order of its reasons moved.

- **Minor: `src/ticket/finish.ts:94-97`. The terminal guard turns a half-finished finish into a final one.** The `blocked` path writes `status: 'blocked'` (`:107`) and the `done` path writes `status: 'done'` (`:132`) *before* the label swap and the note. If either throws there, run.ts's catch-all finish is now a no-op, so the ticket keeps `Loop`. A `done` journal then decides `fresh`, and the next scan re-claims the ticket. If it was `merged: true`, `leaseFor` cuts a new branch and redoes a merged ticket. Before this change, the catch-all at least labelled it `Needs Human`. In practice `editIssueLabels`/`addIssueNote` return results rather than throw, so only an unexpected throw (for example in `mdText`) reaches this. The ruling mandated the no-op; writing the terminal status after the GitLab calls (or catching inside finish) would close the gap.
- **Minor: `src/ticket/session.ts` `sessionMcpServers` (diff lines 2547-2548). A two-entry allowlist makes `project_id` mandatory.** When the numeric id resolves (the normal case), `GITLAB_ALLOWED_PROJECT_IDS` is `"<id>,<path>"`. In 2.2.4 `getEffectiveProjectId` (`index.js:1440-1460`) uses the allowlist ahead of `GITLAB_PROJECT_ID`, and with more than one entry it throws "Multiple projects allowed … Please specify a project ID". So any call that omits `project_id` now errors: `list_merge_requests`/`list_issues` under strict scope, `get_file_contents`, `my_issues`. The prompt never says which `project_id` to use. The error is clear and recoverable, so the cost is turns, not correctness. Also, the server compares paths exactly (case-sensitive) while mr-gate compares case-insensitively; the server is the stricter one, so this is harmless.
- **Minor: `src/ticket/run.ts` `leaseFor` (merged branch).** The fresh lease reuses the merged branch's name. `mergeNow` passes `removeSourceBranch: true` (`merge.ts:54`), so the remote branch is normally gone. If GitLab did not remove it (protected, or removal failed), the session's first push is non-fast-forward, force push is denied by git-guard, and the run ends blocked. The ruling chose same-name; the suffix fallback only covers a failed *local* delete.

## Out-of-Scope Observations

- A ticket that a person merged in `merge.mode: manual` journals `merged: false`, so it never takes the new merged path. If its worktree still exists, `leaseFor` re-attaches the merged branch. After `npm run reap`, `leaseWorktree` finds `refs/heads/<branch>` and re-attaches it (`worktrees.ts:331-334`). This is the review's I2 note for the manual case. The ruling scoped the fix to `merged: true`, and the recommended first live run uses manual mode.
- mr-gate pins the project and, on create, the branches. It does not pin `update_merge_request` or `create_merge_request_note` to this run's MR iid, so another MR on the same project can still be retitled, retargeted to base or commented on.
- The new skip reason ("GitLab has not yet answered who this desk is") is also shown when the desk has no token at all, where `npm run token:set` was the right hint. The ruling mandated this text; the boot banner's `describeIdentity` still says "no usable GitLab token".
- The conductor's background bring-up no longer inherits the operator's shell environment: only the whitelist plus whatever `app.cjs` reloads from `.env`. This is intended and matches the session's own `ensure` and spec §5.2, but a variable exported only in the shell (for example `PG*`) no longer reaches Django.
- Stale "phase" wording remains outside the M17 list: `claudedir.ts:50-61,188-219`, `py-lint.cjs:7-31`, `frontend-test-guard.cjs:15`, `verify-hooks.sh:137-157`.
- secret-guard still does not judge a Grep-tool search rooted at `ONESHOT_HOME` with a broad glob (this predates the fix).
